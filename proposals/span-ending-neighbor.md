# 日本語区間の端のつながりを、実際に隣にあるもので決める

段階: 1 検討

## 問題

- `sonotokihasira` を辞書の変換が「その時柱」にする（「その時は知ら」であるべき）
- `sarigiwagakakkoii` の区切りが sari を英語にし、画面が「sariぎわがかっこいい」になる

## 原因

#74 は、日本語区間の始まりに句点「。」を、終わりに「。」か名詞のうち安い方へのつながりを置いて採点していた。どちらも実際には無いものの推測である。

- 打っている途中の末尾は語や活用の途中で終わるので、終わりのつながりが打ちかけの動詞（知ら）を名詞（柱）に負けさせる
- 採点は 8 かなまでの区間に切って行うので、長い日本語は切れ目ごとに推測のつながりを払い、英語を挟む区切りに負ける（sarigiwa: 日本語だけでは −43.6 未満、sari −17.5 ＋ 際がかっこいい −26.1）

## 決まりの案

| 端 | 隣にあるもの | 扱い |
|---|---|---|
| 始まり | 何も無い | 文の始まり（Mozc の BOS） |
| 始まり | 英語・数字 | 名詞の後・数の後（#74 のまま） |
| 終わり | 入力の末尾、または後でまとめる日本語区間との切れ目 | つながりを足さない |
| 終わり | 英語区間・利用者の語の区間 | 名詞へのつながり |
| 終わり | 句読点・記号 | その記号を Mozc の辞書の語として引き、つながりと語のコスト |

## 基づく原則

- 区間の前後のつながりは、実際に隣にあるもので決める
- 打っている途中の入力の末尾は、文の終わりではない

## 出所

- 文の始まりと、終わりにつながりを足さない扱いは Mozc と同じ（BOS、EOS への連接が 0）
- 英語を名詞とみなすのは #74 の推測で、手本は無い
- 記号を辞書の語として引くのは、Mozc の辞書の行をそのまま使う。？！〜 は辞書で ? ! ～ の字で載っているので、その字で引く
- Mozc は、文頭の助詞や末尾の活用の途中を boundary.def の先頭・末尾の減点で抑えているが、この案は使っていない（試したときは「その時柱」が辞書の変換にも出て、英字が前のかなを巻き込む崩れも増えた）

## 効果

CLI で HEAD と比べた。

| 打鍵 | 辞書の変換（HEAD → 案） | 画面の genmai（HEAD → 案） |
|---|---|---|
| sarigiwagakakkoii | sari際がかっこいい → さり際がかっこいい | sariぎわがかっこいい → 去り際がかっこいい |
| sonotokihasira | その時柱 → その時は知ら | その時柱 → その時柱 |
| nodes | nodes → のでs | nodes → のでs |
| sorede,kyouhagithubnipushsitai | 変わらない | 変わらない |
| korehananndesuka? | 変わらない | 変わらない |
| makewojikkousuru | makeを実行する → 負けを実行する | makeを実行する → 負けを実行する |
| setteiwomakesitedeploysuru | 設定を負けしtedeployする → 設定を負けしてでployする | 設定を負けしtedeployする → 設定を負けしてでployする |

辞書の変換の「さり際」は、Mozc の OSS 辞書に「去り際」の語が無く、ひらがなの「さり」（3336）が「去り」（4084）より安いため。

## 弱点・反例

- 利用者の辞書に英語として登録した `nodes` が「のでs」に負ける（テスト `keepsEnglishKeysOutOfKanaConversion`・`showsTheRegisteredSpellingBeforePunctuation` が落ちる）。HEAD は文頭を「。」の後として日本語の点を下げていたので、登録語が勝っていた。proposals/registered-word-priority.md で扱う
- 文頭の英単語がかなに読めると、日本語に負ける。`makewojikkousuru` は HEAD で make（−13.3）＋を実行する（−16.9）＝ −30.2 が勝っていたが、案では文頭を「。」の後として読まなくなり、負けを実行する（−28.1）が勝つ。docs/how-it-works.md の図の例文である
- `setteiwomakesitedeploysuru` は HEAD でも崩れている（make を 負け、deploy を tedeploy）。案では deploy が「で＋ploy」に割れる
- 英語を名詞とみなすのは推測のまま
- 表示の変換（display）には後ろに続くものを渡さず、開いたまま変換する。画面は genmai が書くので入力メソッドには効かないが、辞書だけの方式では区切りの採点と表示の表記がずれうる
- #74 が endLink で防いでいた「活用の途中で終わる読み（ぶっ飛ん）が英単語に勝つ」が、後ろに英語がある場合に名詞へのつながりで防げているかは確かめていない

## 検証

- 済み: 上の効果の打鍵を CLI で HEAD と比べた。テストは上の 2 件だけ落ちる
- 未: 活用の途中の後ろに英語が続く打鍵、記号の打鍵（zh・[ など）の前で終わる区間
