# 利用者の辞書に登録した綴りを、区切りの点で比べずに優先する

段階: 0 提案

## 問題

- `nodes` を英語の語として登録して `nodes` と打つと、「のでs」になる
- `node` を Node.js として登録して `github,node` と打つと、node が Node.js にならない

## 原因

登録した英語の語の区間は、区切りの点で比べる。点を利用者の語 1 つ分より下げない（max(綴りの点, 登録語の点)）だけで、勝つ保証は無い。#48 は `asitakarahajimeru` で日本語の「明日から」が `kara` の登録に勝つことを記録している。

## 決まりの案

登録した打鍵と一致する区間の両側が、入力の先頭・入力の末尾・句読点・記号・空白なら、点で比べずにその登録語にする。語の途中で一致したときは、今までどおり点で比べる。

## 基づく原則

未定。利用者の発言は「辞書にあるなら辞書を優先でマッチさせるべきだ」。

## 反例

- 両側の条件を付けずに優先すると、`node` を登録したときの `sukinanodesu`（好きなのです）が「好きなNode.jsす」になる

## 決まっていないこと

- 入力の末尾を端に含めるか。原則では入力の末尾は文の終わりではない。含めると、`nodesu` と打ち進めるとき `node` の時点で Node.js が出て、`nodes` で「のでs」に戻る
- 日本語として登録した、かなに読めない打鍵（cafe → Café）にも同じ扱いをするか
