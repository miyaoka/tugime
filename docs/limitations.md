# 現状の制限

誤った表示になる既知の例、tugime が使えなくなる既知の状況と、利用者ができる対処。表示は `tugime-cli --live <打鍵列>` で再現できる（前の文が要る項は `--before <前の文>` も付ける）。その挙動が変わったら、項を直すか消す。

文節だけを直す手順: Shift+Space で文節を選び、← / → と Shift+← / Shift+→ で直したい語に合わせてから、F6（ひらがな）や F10（打ったまま）を押すか、候補から選ぶ。打っている途中に F6〜F10 を押すと、未確定の文字列の全体が変わる。

## ローマ字としても読める英単語が日本語になる

ローマ字としても読める綴りは、綴りだけでは英語か日本語かが決まらないので、日本語として読んだときと点で比べて決める（[変換の仕組み](how-it-works.md#区切りの採点)）。よく使う英単語でも日本語になることがある。誤りを無くす仕組みは無く、判定の変更で減らしていく。

| 打鍵列 | 表示 | 期待 |
|---|---|---|
| `makewojikkousuru` | 負けを実行する | makeを実行する |
| `namewohenkousuru` | 舐めを変更する | nameを変更する |
| `homenomenuwokaeru` | 褒めのめぬを変える | homeのmenuを変える |
| `setteiwohidesitamamanisuru` | 設定を非でしたままにする | 設定をhideしたままにする |
| `asitanomeetingmadeniapinosiyouwosiraberu` | 明日のmeetingまでにアピの仕様を調べる | 明日のmeetingまでにapiの仕様を調べる |

対処: 英語の語の前後をスペースで区切って打つ（`home no menu wo kaeru` は home の menu を 変える）、大文字で打つ（`API`）、tugime の辞書に `en` で登録する、その文節だけを F10 で打ったままに戻す。issue: [#21](https://github.com/miyaoka/tugime/issues/21)

## 子音を打つと、変換されていた全体が英字に戻る

打っている途中、末尾に打ちかけの子音（次に母音を打てばかなになる字）があると、それまで変換されていた部分まで、打ったままの英字で表示されることがある。前の日本語が短いうちに起きやすい。末尾の子音は、打ちかけのローマ字とも英単語の最後の字とも読めるので、打鍵列からはどちらか決まらない。打ちかけを日本語として読むと、英語で終わる入力（`watasiha better`）が日本語に読まれ、Enter でそのまま確定してしまうので、英語として読む側に倒している。

| 打鍵列 | 表示 | 続けて打つと |
|---|---|---|
| `bassis` | bassis | `i` で 抜歯し |
| `bassisit` | bassisit | `a` で 抜歯した |

対処: 母音まで打てば日本語に戻る。打ちかけの子音のまま Enter を押すと、英字のまま確定する。issue: [#139](https://github.com/miyaoka/tugime/issues/139)

## 表示が打った読みどおりにならない

打っている途中の表示は、辞書の語を読みに沿って並べたものではなく、変換モデルが打った読みと前の文から書いた文である。変換が終わる前の打鍵は、かなのまま表示する（[表示の変換](how-it-works.md#表示の変換)）。モデルは文として自然な書き方を選ぶので、打った読みと違う語を書くことがある。Enter を押すと、表示のまま確定する。

| 打鍵列 | 打った読み | 表示 | 期待 |
|---|---|---|---|
| `burauzanankahirakerunda` | ぶらうざなんかひらけるんだ | ブラウザなんか開くんだ | ブラウザなんか開けるんだ |

表示のかなが打った読みのかなと合わないときは、未確定の文字列の下に「入力と違う変換」と出る。この知らせは、かなの違いだけを見る。

- 漢字に変わった部分は、その漢字の読みが打った読みと合うかを見ない。打った読みと違う読みの漢字を書いても知らせない
- 利用者の辞書に登録した語の表記は、登録した打鍵の書き方として扱い、知らせない（`yorosiku` を「よろしくお願いします」と登録したときの「お願いします」）

対処: 「入力と違う変換」が出たら、Enter の前に表示を見直す。打った読みどおりにしたいときは、Shift+Space で文節を選び、候補から選び直す。候補には、辞書の語を打った読みに沿って並べたもの（上の例なら「ブラウザなんか開けるんだ」）も並ぶ。

## Chrome のパスワード欄から別のアプリへ移ると、どのアプリでも使えなくなる

Chrome でパスワード欄にフォーカスしたまま別のアプリへ切り替えると、tugime がどのアプリでも動かなくなる。入力メニューでは tugime が灰色になり、ABC と Apple の日本語入力だけが選べる。

Chrome 156 以降は、パスワード欄にフォーカスしたまま背面に回っても、パスワード欄で有効にした安全入力（Secure Event Input）を解除しない。macOS は安全入力が有効な間、Apple の入力ソースにしかキーを渡さないので、tugime の側では直せない。Chromium の不具合として報告されていて、Edge 157 でも起きる（[577708579](https://issues.chromium.org/issues/577708579)、[567613584](https://issues.chromium.org/issues/567613584)）。

対処: パスワード欄のあるタブを閉じるか、Chrome を終了する。Chrome を終了してから `/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --disable-features=RWHVMacHasFocusReturnsFalseForNonKeyWindow` で起動すると、その起動の間は、背面に回ったときに解除する動きに戻る。このフラグで止まる変更は、背面のウィンドウの自動入力の候補が前面のウィンドウに重なるセキュリティの問題を直すためのもので、止めるとその問題も戻る。安全入力を持っているプロセスは、`ioreg -l -w 0 | grep SecureInput` の `kCGSSessionSecureInputPID` で分かる。
